# 04 — Build-on lineage

Status: open
Type: grilling
Blocked by:

## Question

The Claude doc: "Copier le code est aussi comment vous construisez sur un artefact que quelqu'un d'autre a publié" — you build on a published artifact by copying its code. The pipeline has **preset promotion** (a per-brief look earns a theme-library slot only after a second artifact deliberately builds on it, ticket 19) but no general artifact-to-artifact lineage: no record of which shipped artifact borrowed structure, model, or look from which.

Should the corpus/gallery record formal **"built on X" lineage** — each new artifact's record citing the artifact(s) it derives from (look, interaction pattern, model), making the corpus a real inheritance tree? Or is the record's freeform Notes enough?

Decide: add structured built-on links to records / keep freeform / add lineage only at preset-promotion boundaries.
